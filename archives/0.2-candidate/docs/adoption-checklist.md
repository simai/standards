# First real-project adoption record

Use this record when integrating a real project. The included examples demonstrate
the mechanics but do not count as independent adoption.

| Record | Evidence to capture |
| --- | --- |
| Publisher and resource | Actual owner, resource ID, intended audience and root |
| Source model | Existing authoritative content/API inventory and revision |
| Exported files | Explicit public allowlist and generated manifest/catalog paths |
| Reader | Implementation name/version, profiles, transport and limits |
| User task | A concrete question with product version or a named capability |
| Observed result | Selected item, exact source, revision and extracted example |
| Update test | Changed source produces a new consistent publication |
| Failure test | Missing version, stale digest and denied access are distinguished |
| Human review | Visibility, semantic equivalence, applicability and effects |
| Limitations | Unsupported behavior and unperformed runtime checks |

A pilot is successful when another project can reproduce the intended read path
without knowing the publisher's internal repository or development tools. Record
who authored publisher and reader implementations before calling evidence
independent. Actual production publication and business actions follow the target
project's own authorization and deployment process.

Future process, search, signature and federation work belongs in separate proposals
with a concrete failure in this adopted baseline. No future profile is mandatory
for using core and Knowledge today.
