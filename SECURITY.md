# Reporting security issues

For a specification ambiguity, report a minimal fictional example and the affected
requirement. Do not include credentials, private URLs, customer data or exploitable
production details in a public issue.

For a sensitive implementation vulnerability, use the repository host's private
vulnerability reporting if the owner has enabled it. If no private channel is
available, request one from the repository owner without publishing exploit details.
This initial local distribution does not claim a monitored security inbox or SLA.

The threat model and mandatory reader/publisher boundaries are in spec/security.md.
